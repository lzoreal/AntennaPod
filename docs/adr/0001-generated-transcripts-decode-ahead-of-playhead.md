# 生成转录在播放头之前预读解码，不复用播放 PCM 抽头

**Status**: accepted

为了在播放时有 10–120 秒（默认 30 秒）的提前字幕，生成转录必须在播放头之前拿到音频。仓库里已有 `PcmTapProcessor`（`TeeAudioProcessor`）把解码 PCM 送给广告扫描器，复用它是显然的做法；但抽头与播放头同步，只能看到已经解码到 sink 的音频，无法提前，而且 seek、跳过广告、暂停都会在转录里留下无法控制的空洞。因此生成转录改为由 `:asr` 自行从本地文件或 `SimpleCache` 已缓存字节解码（`MediaExtractor` + `MediaCodec`），按媒体时间渐进产出；播放抽头继续只服务广告扫描。代价是二次解码、流媒体只能读已缓存部分（不足时等播放器下载）、投屏时没有可用的本地位置而禁用生成；换来的是预读窗口、可预期的电量行为，以及与播放状态解耦的时间轴。

**Considered Options**: 只用抽头（无法预读，字幕后置）；抽头 + 缺口补扫双源（两套时间轴合并，复杂度最高）。

**Consequences**: 生成进度跟随播放头，未播放区间只能是缺口；预读窗口是电耗与提前量的唯一旋钮；设备跟不上时缩小窗口而不是丢音频。
